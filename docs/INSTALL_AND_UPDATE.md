# Install and update (Windows factory PC / server)

Release: see `VERSION` and `RELEASE_MANIFEST.json` (package file hashes; this snapshot has no verified commit metadata). This is a **release candidate**: source checks were run in the cloud workspace, but Windows, phone, and factory data are not validated. Do not replace the live installation until the on-phone checklist (`docs/ON_PHONE_CHECKLIST.md`) and a trial on a copy of your data are done.

## Requirements
* Windows 10/11 or Server, 64-bit Intel/AMD. The first start accepts installed CPython 3.11–3.13; if only Python 3.14 is present, it automatically downloads and installs private CPython 3.12 under `RUNTIME\python312` (no admin rights, no PATH change), then creates the app venv. Internet access to python.org and PyPI is required for first setup. Application packages, pip cache and install temp files stay under `RUNTIME` beside the program folder on D:. Cloud tests do not replace a real Windows/mobile network test.
* Internet access **once**, to install the exact dependency versions in `requirements-runtime.txt`. Later Start clicks skip install.
* Optional, only to re-create the PDF/PPTX knowledge register: Tesseract OCR 5 with the `tha` and `eng` language data, and Poppler (`pdftoppm`, `pdftotext`).
* Ports used: 8510 (hub), 8511 (daily), 8512 (firing), 8513 (shared analysis), 8000 (mobile). Allow Python through Windows Firewall on the private factory network only.

## Fresh install (new folder, trial)
1. Unzip `SL_Carborundum_Planning_<version>_<commit>.zip` to a new folder, e.g. `D:\SL\SL_Carborundum_Planning_V16.29-rc11`. The `.sha256` file is only a download check — do **not** copy it into the program folder. If you want to verify the ZIP, compare it with that file, then leave the `.sha256` where you downloaded it. If install stops on pandas / `vswhere.exe`, follow `docs/WINDOWS_INSTALL.md` (install 64-bit Python 3.12; do not install Visual Studio).
2. Double-click `START_SL_CARBORUNDUM_PLANNING_CENTER.bat`. The **first** click on this PC installs the runtime into `RUNTIME\venv` beside the program on D: (several minutes, **once**; factory data is not changed). Later clicks, including a new unzip folder, print **Already installed — starting** and open Streamlit at http://127.0.0.1:8510. Leave the black window open. If install stops on pandas / `vswhere.exe`, follow `docs/WINDOWS_INSTALL.md`. You can still run `INSTALL_REQUIREMENTS.bat` separately if you prefer.
3. To carry forward all audits, photos, user records, QR scan history and source revisions, close the old app and copy the complete current `CENTRAL_DATA` folder into the new program folder before first launch. Copy; do not move, merge selectively, or overwrite the only original. Make a dated backup first. The new app prefers its adjacent `CENTRAL_DATA`; otherwise the launcher can use the legacy `D:\SL_Carborundum_Planning_V16.29-rc14\CENTRAL_DATA` if present. Check the resolved paths in Files & Traceability before using it.
4. Keep the supplied user accounts private; do not put passwords on operator screens or in Line. The Windows account running the app needs read/write access to the local D: data folder.
5. Later starts: the same Start file opens Streamlit immediately. Phones open **http://SERVER-IP:8000/mobile** (no certificate). HTTPS `https://SERVER-IP:8443/mobile` is optional for the live camera after installing `http://SERVER-IP:8000/tls/ca.crt` once (`docs/HTTPS.md`). Mobile users connect to the app over factory Wi-Fi; the phone never accesses the PC's D: drive directly.
6. Use the account issued by your software administrator. Confirm authorized accounts exist in the shared database before opening access; do not put credentials on operator screens.
7. Start on Home by loading or confirming **Plan-2026**. Upload other sources only from the analysis page that needs them (for example the complete firing workbook or only the issued Operator Print sheet on Firing, Production WIP on WIP, one workbook per section on Daily Open / Closed, and both KPI workbooks on KPI Analysis). Each source is retained as a revision and reused by other pages; replace it only when you intend to publish a new revision. Files & Traceability shows the active file and its import details. Stock status is directly available from Home → Quick access → Material status and does not require a Daily Plan calculation.
8. Restore or rebuild the knowledge database: `docs/KNOWLEDGE_DATABASE.md`.
9. Run `RUN_SELFTEST.bat`, then `python apps\daily\VERIFY_RELEASE.py` and `python apps\firing\VERIFY_RELEASE.py`.

## Update an existing installation (without touching data)
Active factory data lives under the selected `CENTRAL_DATA` folder beside the app or, when that folder is absent, the legacy `D:\SL_Carborundum_Planning_V16.29-rc14\CENTRAL_DATA`. Two folders inside older program folders may also hold historical data: `apps\mobile\qr\` (generated QR labels) and `apps\mobile\uploads\` (original uploaded work-order files), plus `apps\mobile\data\` (an older database). Keep the old program folder until historical QR labels and source uploads are checked.
1. Stop the services (close the planner windows or `control_center.py`).
2. **Back up first** (`docs/MIGRATION_BACKUP_ROLLBACK.md`): the whole `SL_SHARED_ROOT` folder and the old program folder. Do not skip this.
3. Unzip the new release into a **new sibling folder**. Do not unzip over the old one.
4. Keep the package's `SERVER_STORAGE_CONFIG.bat`. It prefers a copied program-local `CENTRAL_DATA`, then uses the legacy D: root. It does not clear either folder. Do not delete or replace the original data until the new version is confirmed to show audit history and photos.
5. Start the new folder. It reuses the shared runtime already installed on this PC (pip runs again only if `requirements-runtime.txt` changed). Active application data continues under the D: root. The app may make an automatic database backup before additive schema migration.
6. Check Files & Traceability resolves to the copied `CENTRAL_DATA`; verify prior audit records, photos, QR scan history, and source revisions are visible. The update does not generate new labels or change the existing QR payload. Existing printed labels continue to be scanned as before.
7. Keep the old folder until you are satisfied. Rolling back = stop, start the old folder (see rollback notes).
