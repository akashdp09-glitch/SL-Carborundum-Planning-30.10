V16.11 CHANGES
- Work Order QR payload defaults to SLWO:<WO ID>; no detected/current LAN IP is embedded.
- Desktop QR registry versioned as SLWO:v1. On first generation, previous IP-based QR registry entries are treated as old and all current WOs are regenerated. Later “new WOs” generation skips only WOs already recorded under SLWO:v1.
- Mobile QR Generator is directly linked in the app navigation. It creates one PNG or a printable workbook. Optional direct-open labels require an explicit stable SL_PUBLIC_URL.
- Mobile scan flow attempts live browser camera where available and exposes phone camera/photo capture as fallback. Photo-based scans save the submitted image, SHA-256, decoded payload, WO, operator, method, result, and time. Failed photo scans are retained for diagnosis. Live camera scans log their payload and result but do not store an image frame.
- Work Order source imports record saved absolute path and SHA-256. QR workbook generation is now on-demand instead of blocking every import.
- Search uses bounded SQL queries and indexed exact WO/production-code fields. SQLite WAL is enabled once at initialization, avoiding a journal-mode change on each request.
