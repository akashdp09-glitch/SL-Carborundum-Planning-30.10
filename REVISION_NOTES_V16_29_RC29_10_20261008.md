# V16.29-rc29.10 — dashboard traceability, report data, and one-click startup

## UI and responsiveness

- Home and quick-access tiles now use larger standalone icons and smaller labels. On narrow phone screens, tiles use two columns with reduced gaps and padding. This is CSS/HTML only; no images or extra network calls were added.
- The home hero image remains cached and local, so the tile change does not add image decode or download work.

## Requested changes

- The launcher now checks the full pinned app runtime and its requirements stamp. A valid existing runtime opens the app directly.
- Setup creates the Windows Desktop shortcut `SL Carborundum Planning Center`. The shortcut launches the app through the same Start file and does not repeat installation.
- Runtime and private Python are stored under `D:\SL_Carborundum_Planning_V16.29-rc14\RUNTIME`, shared when extracting a new version folder. A dependency revision may update packages once.
- Existing `CENTRAL_DATA` paths remain unchanged; database, scan photos, QR records and audit photos are outside the program ZIP.
- Dashboard HTML now retains Plan-2026 Thai customer names alongside readable Latin companions, adds product specification to order lists, and records active source file names, modified time and the snapshot fingerprint.
- Weekly/daily/monthly/quarterly Plan-vs-Actual views use selectable From/To dates. The KPI workbook analysis uses dated workbook rows for the trend; the Plan-2026 cumulative fields are labeled separately and future actuals are not invented.
- Charts display their source file names; full file paths, revision and import time remain in Files & Traceability.
- Backorder Thai editor config now follows each column’s actual pandas type. Numeric quantity fields remain number columns.
- The management report now seeds daily planned Packing output, dated Daily Status actuals, process capacity/load, Mixing mill counts, current firing rows and current risk rows from loaded data. Dispatch confirmation and material sufficiency remain unconfirmed unless an explicit source supports them. Planning WIP is shown from the Plan-2026 master where those fields exist.
- Every hub page has a compact “You are here” bilingual title.

## Checks

- Python syntax compilation passed for the hub, daily planner, daily management report, runtime helper and customer-name helper.
- Windows installer, desktop shortcut creation, live camera, and live factory database were not executable in this Linux workspace. The shortcut is implemented with Windows PowerShell COM and requires no admin rights.
- Pytest is not installed in this workspace; focused tests could not be executed here.


# Follow-up hotfix — dashboard and session/data retention

- Fixed the dashboard HTML `NameError` by building an escaped, source-file-name caption from the supplied source references before rendering the HTML. Missing paths are labeled; they no longer stop dashboard creation.
- Daily Planner meeting-size text now starts OFF; the user can turn it on.
- Daily plan snapshots are written append-only under `CENTRAL_DATA/CACHE/DAILY_PLAN_SNAPSHOTS/`, and the current pointer is atomically replaced. A prior plan is restored for review when source file bytes are unchanged even if view controls differ. If active source bytes change, the prior result remains visible as a dated snapshot with a stale-source warning and must be recalculated before release. Startup recovers the newest valid dated snapshot if the current pointer is missing or damaged.
- Recovery action commitments now have an editable table and append-only CSV revisions under `CENTRAL_DATA/RECOVERY/ACTIONS/`; save records the current username and Thailand timestamp. Exports include the edited recovery action record. The plan remains a draft until Sales/Production confirmation.
- Recovery view shows the quantity already included in the unified daily plan versus open recovery quantity, daily section capacity evidence, and date/section indicative overtime from the current load. The OT figure is not approval and is not isolated to recovery WOs.
- Mixing gets a dedicated mill-count graph with planned mills assigned, actual mills active and active mills/day from the capacity register; units are explicitly shown as mills. Batch capacity and kg remain separate. Removed the phrase “non-stacked” from capacity chart headings.
- Added a second connection QR for the section OPEN/CLOSED entry page. The host PC stores entries in its configured D: `CENTRAL_DATA`; client phones/computers do not need direct D: or Z: access. The factory host must remain on and reachable on Wi-Fi.
- The existing local company-front image and logo are embedded from the package and cached; no web image download or new dependency was added.

## Verification limits

Syntax compilation and archive/hash integrity checks pass. The real Windows installer, deployed Streamlit sessions, company firewall/Wi-Fi, phone camera and multiple simultaneous users have not been verified in this environment. Full inline editing of generated daily allocations is not claimed by this follow-up: existing planner decision/route overrides and firing-plan editing remain the controlled edit mechanisms; the recovery commitments are now editable and saved centrally.


## RC29.12 persistence correction (2026-10-08)

- Fixed the remaining data-reset path: changing an active source revision no longer clears the last daily calculation from the open session. It stays visible with a stale-source warning, and the user can create a new calculation from the current sources when ready.
- On a fresh browser/app session, the planner restores the current saved calculation even when its source fingerprint differs; if the current pointer is missing or unreadable, it scans the append-only `CENTRAL_DATA/CACHE/DAILY_PLAN_SNAPSHOTS/` folder and restores the newest readable successful result. It never labels an old snapshot current or release-ready.
- Login remains active during in-app navigation and across hub links through the signed session handoff. Only the explicit **SWITCH LOGIN** action clears it. The password itself is not saved in planner snapshots.
- Validation: Python syntax compile and ZIP/manifest/hash integrity checks. Actual Windows app navigation and multi-user use still require confirmation on the host PC.
