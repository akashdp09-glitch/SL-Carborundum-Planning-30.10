# V16.29-rc29.29 — Operator Print firing-source support

## Firing source update

- The Firing source accepts either a full firing workbook or only the issued `Operator Print` sheet. Required headers are Work Order, Kiln, Loading Date, planned quantity, and Firing Complete / finish date. The supplied `FIRING_PLAN_9.10.2026 prod.xlsx` was recognized as an Operator Print-only source (661 data rows).
- The uploaded source is validated before activation. An unsupported or incomplete workbook is rejected and does not replace the current active source. The source manager retains import history and the original upload.
- The previous-load kiln protection reads the print-only sheet, groups work orders by load so a shared kiln load is protected once, and uses recorded finish dates or explicit running days. It does not invent a missing cycle duration. The audit records each load and the finish evidence.
- Daily Planner's existing firing workbook loader also reads the supplied print-only workbook (661 rows). The same active source is reused by Firing and Daily after upload.

## Preserved data and QR labels

- This update leaves the established QR payload (`SLWO:<WO>`) and QR generation code unchanged. Issued labels do not need reprinting.
- The ZIP excludes live `CENTRAL_DATA`, databases, audit photos, and scan history. Keep and copy the existing complete `CENTRAL_DATA` folder beside the extracted new program before launch; do not replace it with an empty folder. Existing database and picture paths remain under `CENTRAL_DATA`.
