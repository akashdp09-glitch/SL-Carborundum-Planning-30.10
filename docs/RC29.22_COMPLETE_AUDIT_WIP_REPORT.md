# RC29.22 — Complete audit, part status and WIP report

Release date: 2026-10-10 (Thailand time basis)

## Desktop report

On **Track / QR → Audit Report**, use **Build Complete Audit + Part Status + WIP Report**, then download the workbook. The report is generated only after the user clicks the button; entering the page and changing tabs do not rebuild it.

Workbook sheets include:

- `READ ME + SUMMARY` — snapshot time, active Plan-2026, audit/event/photo counts, and WIP definitions.
- `Audit summary`, `Audit by_category`, `Audit by_date`, `Audit by_status`, `Audit by_location`, `Audit by_process`, and `Audit by_location_comparison` — all physical audit events, with category/date/status/location/process and plan-vs-physical location comparison.
- `Plan WO STATUS` — active Plan-2026 part/order and open/closed fields available to the signed-in user.
- `ALL PHYSICAL AUDITS` — every submitted audit record, including quantity, status, location, user and time.
- `PHOTO EVIDENCE` — each stored audit photo’s audit ID, WO, status, section, filename, storage path, SHA-256 and embedded thumbnail. Full image files remain in `CENTRAL_DATA\PHOTOS\MOBILE_AUDITS`.
- `SECTION EVENT HISTORY`, `QR SCAN LOG`, and `UNIDENTIFIED PARTS` — status/movement events, scan outcomes/evidence references, and parts without a WO.
- `PLAN-2026 OPEN WIP` — planning open-balance measure.
- `SCAN EVENT WIP` — remaining order quantity by last recorded scan process; this is not a physical count.
- `PRODUCTION WIP SNAPSHOT` — section workbook report, units and source/import metadata.

WIP measures are deliberately not added together. Reconcile them only after confirming the same cutoff and process basis. Photo thumbnails are optimized for the workbook; the original picture files are retained unchanged in the active `CENTRAL_DATA` photo folder. Large reports can take time to build and download, so generation is manual and on demand.

## Other changes carried forward

RC29.22 includes RC29.21’s section/date-filtered QR labels (uppercase WO directly under QR), program-local `CENTRAL_DATA` priority, and distinct overdue versus due-today/future graphs. It keeps the RC29 mobile audit service and data model; this update adds a desktop report and does not migrate or delete live data.

## Validation and limits

- Python syntax compilation and synthetic backorder/recovery tests are run for this release.
- The combined workbook has not been exercised against a real factory database containing thousands of images. Generate one from a copy of `CENTRAL_DATA` first and confirm images, permissions, and workbook size.
- Windows startup, phone QR scanning/camera, live workbook reconciliation, actual printer output, and concurrent shop-floor load remain factory-PC checks. No cloud test can certify those conditions.
